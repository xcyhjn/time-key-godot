# Unity 3D 产品边界

> 状态：首切片边界已冻结
> 负责人：主智能体
> 最后验证日期：2026-07-31
> 证据来源：Godot 双视口截图、`HexUtils.gd`、`hex_map.gd`、`project.godot`

## 采用“3D 世界 + 2D 信息层”

**决策**：局外地图、局内战场、地块、单位/建筑、镜头、灯光和世界反馈使用真实 Unity 3D；卡牌、3×12 时间轴、tooltip、菜单和高密度数值使用屏幕空间 uGUI。

这不是视觉降级。它把深度、空间关系和目标反馈放进 3D，同时保留卡牌文字与时间轴的可读性。

## 局外六边形地图

- flat-top 六边形 3D mesh，轴坐标 `(q,r)` 为领域真值。
- 房间类型用 3D 标记、色带和形状三重编码；路径使用世界空间线/桥。
- 相邻可达格同时提供轮廓、抬升和地面环，不能只靠颜色。
- 正交斜俯视镜头跟随当前房间；拖动/缩放保留，但点击判定由 raycast 到格子 collider。

## 局内战斗

- 六边形占 XZ 平面，Y 表示堆叠高度；1 世界单位作为首切片 hex radius。
- 地形、建筑、敌人、核心分开节点/组件；目标选择反馈使用 emissive/outline 与地面 decal。
- 伤害、治疗、毒、建造和高度变化先用颜色、位移、数值弹字完成白盒反馈。
- 3D 世界只显示需要空间定位的信息；精确 HP、行动顺序仍在 UI。

## 镜头与坐标

**决策**：首切片使用正交 3D 斜俯视镜头。正交投影保留原作网格可判读性，真实几何高度、阴影、遮挡和材质仍提供 3D 深度。若后续要改透视，必须以同样的格子点击准确率和 UI 可读性截图为门禁。

Unity 坐标约定：

```text
X = 右
Y = 上/地块高度
Z = 屏幕纵深
flat-top axial(q,r) → world(
  x = 1.5 * radius * q,
  y = elevation * elevation_step,
  z = sqrt(3) * radius * (r + q/2)
)
```

领域层不得存 `Vector3`；只存 `HexCoord(q,r)` 与整数 elevation。

## 美术三层

| 层级 | 用途 | 首切片规则 |
| --- | --- | --- |
| 白盒 | 验证规则、镜头、深度和输入 | Unity 原生 mesh、程序化材质、默认字体 |
| 过渡资产 | 验证风格和信息层级 | 只使用授权已确认的 2D billboard/decal/音频 |
| 目标资产 | 发布质量 | 在玩法与性能门禁后制作/采购模型、动画、材质 |

禁止在白盒玩法尚未通过时批量生成最终模型。

## 中文与无障碍

- UI 默认最小正文目标字号 18 px（1080p 基线），小视口不低于可读阈值。
- 颜色状态必须有形状/图标/文字冗余；敌我和合法/非法不能只靠红绿。
- tooltip 需要自动换行、屏幕边缘翻转和键鼠焦点路径。
- ARK Pixel 字体授权未确认前不复制到 Unity；首切片用 Unity 可用默认字体并避免依赖中文截图作为最终授权证据。

## 首切片视觉验收

- 1920×1080、1280×720 两个窗口实际截图。
- 3D 六边形轮廓、至少两个高度层和一个目标单位清楚可辨。
- 主目标、HP、回合、时间轴与卡牌无裁切/重叠。
- 从选择目标到时间轴放置的反馈连续可理解。
- 只有实际渲染截图通过才标记视觉完成。
