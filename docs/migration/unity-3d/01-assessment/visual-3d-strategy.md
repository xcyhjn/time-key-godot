## 采用“3D 世界 + 2D 信息层”

**决策**：当前只将局内战场、地块、单位/建筑、镜头、灯光和世界反馈迁移为 Unity 3D；卡牌、3×12 时间轴、tooltip 和高密度数值使用屏幕空间 uGUI。局外地图与流程暂时保持 Godot 现状。

这不是视觉降级。它把深度、空间关系和目标反馈放进 3D，同时保留卡牌文字与时间轴的可读性。

## 局外六边形地图

- 不在当前实现范围。
- 房间选择、路线、奖励返回和存档继续使用 Godot，直到用户重新排定优先级。

## 局内战斗

- 六边形占 XZ 平面，Y 表示真实堆叠层；外接半径 `0.94`，每层实体高 `0.32`。
- elevation 0 是一层实体块，elevation 1 是两层 mesh/collider；禁止只把顶面整体抬高。
- 地形、建筑、敌人、核心分开节点/组件；目标选择反馈使用 emissive/outline 与地面 decal。
- 伤害、治疗、毒、建造和高度变化先用颜色、位移、数值弹字完成白盒反馈。
- 3D 世界只显示需要空间定位的信息；精确 HP、行动顺序仍在 UI。

## 镜头与坐标

**决策**：局内棋盘使用透视斜俯视轨道镜头。右键旋转、中键平移、滚轮缩放；水平 360 度，俯仰 `24..72` 度，距离 `7..18`。旋转不得清空选卡、目标或时间轴状态。

Unity 坐标约定：

```text
X = 右
Y = 上/地块高度
Z = 屏幕纵深
flat-top axial(q,r) → world(
  x = 1.5 * radius * q,
  y = layer_index * 0.32,
  z = sqrt(3) * radius * (r + q/2)
)
```

领域层不得存 `Vector3`；只存 `HexCoord(q,r)` 与整数 elevation。

## 美术三层

| 层级 | 用途 | 首切片规则 |
| --- | --- | --- |
| 白盒 | 验证规则、镜头、深度和输入 | Unity 原生 mesh、程序化材质、默认字体 |

## 中文与无障碍

- UI 默认最小正文目标字号 18 px（1080p 基线），小视口不低于可读阈值。
- 颜色状态必须有形状/图标/文字冗余；敌我和合法/非法不能只靠红绿。
- tooltip 需要自动换行、屏幕边缘翻转和键鼠焦点路径。
- ARK Pixel 字体授权未确认前不复制到 Unity；首切片用 Unity 可用默认字体并避免依赖中文截图作为最终授权证据。

## 首切片视觉验收

- 1920×1080、1280×720 两个窗口实际截图。
- 3D 六边形轮廓、至少两个高度层和一个目标单位清楚可辨。
- 主目标、HP、回合、时间轴与卡牌无裁切/重叠。
- 从选择目标到时间轴放置的反馈连续可理解。
- 只有实际渲染截图通过才标记视觉完成。
