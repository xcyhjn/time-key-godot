# ADR-0002：局内战斗棋盘采用透视轨道镜头与实体六边形堆叠

> 状态：Accepted
> 日期：2026-07-31

## 背景

用户迁移到 Unity 的首要目的，是把局内战斗棋盘做成可平滑交互、可 360 度检查的 3D 战棋地图。卡牌、敌人行为、时间轴、UI、素材与风格继续以原 Godot 项目为准；局外地图和章节流程暂不迁移。

Slice 01 的正交 9 格白盒只能证明规则链路，不能验证自由检查、高度遮挡、旋转后选格或 UI 输入泄漏。

## 决策

- 当前范围只包含局内战斗棋盘；局外保持现状，未经新的用户决策不得启动 3D 局外波次。
- 使用透视轨道相机：右键旋转、中键平移、滚轮缩放；yaw 连续 360 度，pitch `24..72` 度，距离 `7..18`。
- 当前相机用窄职责 `BoardOrbitCameraController` 实现并暴露确定性测试入口。待输入重映射、手柄或镜头混合成为实际需求时，再评估 Cinemachine/Input System，避免在棋盘基线阶段同步引入包迁移。
- UI 与世界选择统一经过屏幕空间门禁；UI 覆盖区域不得向世界 raycast 泄漏。
- elevation 是实体层数，不是顶面位移：单层高度 `0.32`，高度 0 生成一层，高度 1 生成两层独立 mesh/collider，依此类推。
- 领域层仍只保存 `HexCoord(q,r)` 与整数 elevation；Presentation 负责转换为 XZ 坐标和 Y 轴实体堆叠。
- 地块可视层使用可复现 Blender 源文件与 FBX，碰撞和层数仍由运行时控制器掌握。
- 原敌人/建筑 PNG 作为完整面向相机的世界 billboard；卡牌和 3×12 时间轴继续使用屏幕空间 uGUI。

## 结果

- 旋转、缩放和平移不会改变当前卡牌/目标状态。
- 同一目标必须能从 0/90/180/270 度 raycast 选中。
- 美术模型可替换而不修改六边形坐标、碰撞或结算契约。
- 任意新高度效果必须生成/移除真实块并同步碰撞，禁止只改顶面 Y。

## 验证

- EditMode 19/19、PlayMode 4/4。
- 19 格棋盘、两处双层高地、四向 1920×1080 与 1280×720 实际截图。
- Windows Player 构建和固定交互冒烟通过。
- Blender 草地/裸土地块均为 120 三角形、实体高 0.32、0 非流形边；双层无间隙。
